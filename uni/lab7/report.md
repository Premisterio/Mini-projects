## Опис реалізації

Гра реалізована **одним файлом `index.php`** + стилі. Архітектура — класичний **PRG-патерн** (Post-Redirect-Get): кожен хід надсилається через POST-форму, сервер оновлює стан у сесії та робить редирект на ту ж сторінку, після чого браузер виконує GET. Це гарантує, що F5 не повторить останній хід.

### Стан гри зберігається в `$_SESSION`
- `board` — масив із 9 елементів (`''`, `'X'` або `'O'`)
- `turn` — чий зараз хід
- `winner` — `null`, `'X'`, `'O'` або `'D'` (нічия)
- `score` — глобальний рахунок між раундами

## Фрагменти коду

### 1. Ініціалізація гри
```php
function new_game(): void {
    $_SESSION['board']  = array_fill(0, 9, '');
    $_SESSION['turn']   = 'X';
    $_SESSION['winner'] = null;
    $_SESSION['score']  = $_SESSION['score'] ?? ['X' => 0, 'O' => 0, 'D' => 0];
}
```
**Що робить:** скидає дошку та чий хід, але **зберігає загальний рахунок** між раундами (через `??` — якщо ще не існує, створює).

### 2. Перевірка перемоги
```php
function check_winner(array $b): ?string {
    $lines = [
        [0,1,2],[3,4,5],[6,7,8],  // горизонталі
        [0,3,6],[1,4,7],[2,5,8],  // вертикалі
        [0,4,8],[2,4,6],          // діагоналі
    ];
    foreach ($lines as $l) {
        if ($b[$l[0]] !== '' && $b[$l[0]] === $b[$l[1]] && $b[$l[1]] === $b[$l[2]]) {
            return $b[$l[0]];
        }
    }
    return in_array('', $b, true) ? null : 'D';
}
```
**Що робить:** перебирає 8 виграшних ліній. Якщо знаходить три однакові непорожні символи — повертає переможця. Якщо ні і вільних клітинок не лишилось — повертає `'D'` (нічия).

### 3. Обробка ходу (POST-частина)
```php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    if (isset($_POST['reset'])) {
        new_game();
    } elseif (isset($_POST['cell']) && $_SESSION['winner'] === null) {
        $cell = (int)$_POST['cell'];
        if ($cell >= 0 && $cell < 9 && $_SESSION['board'][$cell] === '') {
            $_SESSION['board'][$cell] = $_SESSION['turn'];
            $result = check_winner($_SESSION['board']);
            if ($result !== null) {
                $_SESSION['winner'] = $result;
                $_SESSION['score'][$result]++;
            } else {
                $_SESSION['turn'] = $_SESSION['turn'] === 'X' ? 'O' : 'X';
            }
        }
    }
    header('Location: ' . $_SERVER['PHP_SELF']);
    exit;
}
```
**Що робить:**
1. Якщо натиснули "Нова гра" — скидає стан.
2. Інакше валідує номер клітинки (0–8) і перевіряє, що вона вільна та гра ще не закінчена.
3. Ставить символ, перевіряє перемогу. Якщо немає — передає хід супернику.
4. Робить редирект (PRG-патерн).

### 4. Тернарний `match` для статусу
```php
$status = match (true) {
    $winner === 'D'   => 'Нічия!',
    $winner !== null  => "Переміг гравець «{$winner}»!",
    default           => "Хід гравця «{$turn}»",
};
```
**Що робить:** використовує PHP 8 `match` для лаконічного вибору тексту статусу.

### 5. Рендеринг дошки
```php
<form method="post" class="board">
    <?php foreach ($board as $i => $mark): ?>
        <button
            type="submit"
            name="cell"
            value="<?= $i ?>"
            class="cell <?= $mark ? 'cell-'.strtolower($mark) : '' ?>"
            <?= ($mark !== '' || $winner !== null) ? 'disabled' : '' ?>
        ><?= htmlspecialchars($mark) ?></button>
    <?php endforeach; ?>
</form>
```
**Що робить:** генерує 9 кнопок у формі. Зайняті клітинки та клітинки після завершення гри блокуються (`disabled`). Використано `htmlspecialchars()` як захист від XSS (хоч тут вміст і контрольований).

## Висновки

У ході роботи опановано базові концепції серверного програмування на PHP:
- робота з суперглобальними масивами `$_SESSION`, `$_POST`, `$_SERVER`;
- змішування PHP-коду з HTML через короткий синтаксис `<?= ?>`;
- обробка форм за патерном **Post-Redirect-Get**, який запобігає повторному надсиланню при F5;
- сучасні можливості PHP 8 (`match`, типізація аргументів та повернення, nullable-типи `?string`).

**Критичний аналіз:**
- Реалізація **stateful через сесії** означає, що стан прив'язаний до cookie конкретного браузера — два гравці на різних пристроях гру одночасно не побачать. Для мультиплеєра потрібна БД або WebSocket.
- Кожен хід — це повний request-response цикл із перезавантаженням сторінки. Це навмисно для демонстрації серверної логіки, але в реальному застосунку природніше робити це через AJAX чи Fetch API.
- Логіки штучного інтелекту немає — гра тільки PvP "hot-seat" на одному пристрої. Простий бот реалізується через мінімакс на ~30 рядках.
- Захист CSRF не реалізовано — у навчальному прикладі це прийнятно, у реальному застосунку обов'язковий CSRF-токен у формі.

Поставленої мети досягнуто: гра працює, перевіряє всі 8 ліній перемоги, фіксує нічию, веде рахунок між раундами та коректно деплоїться на shared-хостинг із підтримкою PHP.
